# Demo-only dependencies, installed by the Dockerfile: CPU-only, no torch, no project install.
#
# Not the development environment: development, EDA and training use the pyproject.toml extras
# via uv (`make setup`, `make setup-train`, scripts/bootstrap_cloud.sh). Keep these floors in
# step with the core dependencies and the [demo] extra in pyproject.toml.
#
# Streamlit Community Cloud does not use this file. It installs from the first dependency file
# it finds, searching the entrypoint's directory before the repo root, in the order
# uv.lock > Pipfile > environment.yml > requirements.txt > pyproject.toml, so the committed root
# uv.lock would otherwise win. The file next to the app takes precedence there:
# src/shopsage_rec/serving/requirements.txt, generated with
#   uv export --frozen --no-hashes --no-emit-project --extra demo -o <that path>
# plus a two-line sys.path shim in app.py, since the project is not installed there either.
#
# - No local "." line: the Dockerfile sets PYTHONPATH=/app/src instead of installing the
#   project, so core dependencies the demo does not use (typer for the CLI, duckdb for EDA)
#   stay out of the image. The app must not import torch, typer or duckdb; CI's demo-deps job
#   installs this file alone and checks the imports.
# - LightGBM needs the OpenMP runtime: libgomp1 (Dockerfile; root packages.txt on Community Cloud).
# - streamlit>=1.41: the first release that accepts the string client.showErrorDetails values
#   used in .streamlit/config.toml and `make demo`.
